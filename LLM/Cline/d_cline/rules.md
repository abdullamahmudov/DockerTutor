# Cline Agent Rules — Anti-Loop & Quality Discipline

Эти правила применяются ко ВСЕМ задачам. Их цель: агент не зацикливается,
не додумывает требования и всегда завершает задачу проверенной работой.

## 1. Anti-Loop Rule (главное против зацикливания)
Если одно и то же действие/команда не дало нового результата 2 раза подряд:
1. Остановиться. НЕ повторять в третий раз.
2. Явно проанализировать, ПОЧЕМУ не сработало — прочитать ошибку целиком.
3. Сменить подход (другая команда / другой файл / уточнить у пользователя).
4. Если 3 разных подхода не помогли — остановиться и спросить пользователя.

## 2. Stop-Criterion Rule (критерий остановки в каждом шаге)
Каждый шаг плана должен содержать проверяемый критерий готовности, а не просто действие:
- Плохо: "Запустить тесты"
- Хорошо: "Запустить `npm test`; готово, когда exit code = 0 и нет fail. Если fail — читать имя упавшего теста."

## 3. Error Handling Rule (сначала читай ошибку)
При ошибке команды/теста:
- НЕ переписывать код вслепую. Сначала прочитать полный текст ошибки.
- Сформулировать гипотезу одной строкой, потом менять минимум кода под неё.

## 4. Tool Discipline Rule (минимум инструментов / анти-раздувание контекста)
- Для консультативных вопросов отвечать напрямую, без запуска инструментов.
- Читать только файлы, реально нужные для шага; не обходить весь проект подряд.
- Не запускать скилл/инструмент «на всякий случай».

## 5. Definition of Done (верификация = часть задачи)
Задача завершена ТОЛЬКО когда: код написан + запущен (сборка/тесты зелёные) + diff просмотрен.
"Написал" ≠ "готово".
