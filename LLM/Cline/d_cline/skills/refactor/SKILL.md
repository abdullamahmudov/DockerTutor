# /refactor — Рефакторинг с сохранением поведения

Цель: улучшить структуру/читаемость кода БЕЗ изменения внешнего поведения. Обязательные тесты до и после гарантируют, что поведение не сломано.

## Когда запускать
Код работает, но: дублирование, длинные функции, плохие имена, высокая связанность, магические числа, нарушение конвенций проекта.

## Что сделать (порядок обязателен)
1. **База**: убедиться, что есть тесты покрывающие текущее поведение И они зелёные. Если нет — сначала написать characterization-тесты (фиксируют ТЕКУЩЕЕ поведение). Запустить: зелёный.
2. **Минимальный шаг рефакторинга** (один за раз): переименовать / вынести функцию / убрать дублирование / упростить условие. Не совмещать с изменением логики.
3. **Проверить**: запустить тесты после КАЖДОГО шага. Готово: всё ещё зелёный. Если упало — откатить шаг, читать ошибку (Error Handling Rule).
4. Повторять 2–3 до достижения цели.

## Правила рефакторинга
- Один рефакторинг = один тип изменения. Не «пока я тут» менять логику.
- Следовать конвенциям проекта (/context): имена, структура, существующие паттерны.
- Убирать: дублирование, мёртвый код, магические числа (→ именованные константы), вложенность > 3 уровня, функции > ~50 строк.
- Не повторять упавший тест > 2 раз без смены подхода (Anti-Loop Rule).

## Definition of Done
Тесты до == тесты после (все зелёные) + поведение не изменилось + код стал читабельнее + diff просмотрен.
