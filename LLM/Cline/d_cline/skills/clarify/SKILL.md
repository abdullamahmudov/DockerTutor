# /clarify — Уточнение требований

Цель: убрать домыслы — главный источник «сделал не то». Перед стартом задачи, если она неоднозначная, задать уточняющие вопросы.

## Когда запускать
- Задача сформулирована размыто («оптимизируй», «почини», «улучши»).
- Есть несколько равноправных интерпретаций.
- Затрагиваются публичные API / данные / безопасность (решения необратимы).

## Что сделать
1. Прочитать запрос и текущий контекст (минимум файлов, только нужные).
2. Выписать **неопределённости** — что именно неясно.
3. Сформулировать 2–5 конкретных вопросов с вариантами ответов (чтобы пользователю было легко выбрать, а не писать с нуля).

## Правила
- Не более 5 вопросов за раз; сначала самые блокирующие.
- Каждый вопрос — конкретный и с вариантами, а не «а что ты имел в виду?».
- НЕ начинать реализацию до ответов на блокирующие вопросы.
- Если задача тривиальна и однозначна — пропустить скилл (Tool Discipline: минимум действий).

## Формат вопроса
```
Вопрос: Как обрабатывать дубликаты при импорте?
  a) игнорировать новые, оставить старые
  b) перезаписывать старые новыми
  c) ошибка и остановка импорта
```

## Финальный вывод
Список вопросов с вариантами. Стоять до ответов, затем перейти к /plan или реализации.
