# /tdd — Test-Driven Development

Цель: сначала тест → минимум кода → зелёный тест → рефакторинг. Ошибка ловится сразу, а не в конце. Агент физически не может «сделать и забыть проверить».

## Цикл (повторять для каждой единицы поведения)
1. **RED** — написать один failing-тест на желаемое поведение. Запустить: он должен упасть с понятной причиной (не из-за синтаксиса, а из-за отсутствия логики).
2. **GREEN** — написать МИНИМУМ кода, чтобы тест прошёл. Не оптимизировать, не добавлять «пока что» фичи. Запустить: зелёный.
3. **REFACTOR** — при зелёном свете убрать дублирование/улучшить имена, НЕ меняя поведение. Запустить снова: всё ещё зелёный.

## Правила
- Один тест = одно поведение (один assert на смысл).
- Тесты пишутся ДО реализации, не после «чтобы было».
- Если тест падает по неожиданной причине — читать ошибку целиком, формулировать гипотезу одной строкой, менять минимум кода.
- Не запускать один и тот же failing-тест > 2 раз без смены подхода (Anti-Loop Rule).

## Definition of Done
Все новые тесты зелёные + существующие не сломаны + код покрыт тестами для нового поведения.
