# /context — Сбор контекста проекта

Цель: структурированный обход, чтобы агент работал в рамках конкретного стека и конвенций проекта, а не по общим шаблонам. Снижает ошибки «не так как у вас принято».

## Что собрать (только нужное для текущей задачи)
1. **Стек**: язык, фреймворки, версии (package.json / pyproject.toml / go.mod / Cargo.toml и т.п.).
2. **Команды**: build, test, lint, run — найти в конфиге/CI/README, НЕ гадать.
3. **Конвенции именование** и структура: как называются файлы/функции/компоненты, где что лежит.
4. **Существующие паттерны**: как решаются похожие задачи (найти 1–2 примера в коде).
5. **Ограничения**: CI-правила, лимиты, обязательные проверки перед коммитом.

## Правила
- Читать только файлы, реально нужные для шага; не обходить весь проект подряд (Tool Discipline).
- Использовать поиск по коду (regex) вместо последовательного чтения файлов.
- Если контекст уже собран в текущей сессии — не собирать заново.

## Финальный вывод
Краткая сводка: стек + версии, команды запуска/тестов, ключевые конвенции, найденные примеры паттернов. Использовать как основу для /plan или реализации.
