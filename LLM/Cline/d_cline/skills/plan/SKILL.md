# /plan — Планирование перед кодом

Цель: запретить писать код до утверждённого плана. Сначала анализ и чек-лист шагов, потом исполнение. Это главный антизацикливатель.

## Когда запускать
Перед любой нетривиальной задачей (новая фича, багфикс > 1 файла, рефакторинг). Для тривиальных правок — можно пропустить.

## Что сделать
1. **Собрать контекст**: прочитать только файлы, реально нужные для задачи (не весь проект). Определить: стек, конвенции именование, команды запуска/тестов.
2. **Уточнить требования** (если неоднозначно): задать 2–5 вопросов пользователю ДО плана. Не додумывать.
3. **Написать план** в виде нумерованного чек-листа. Каждый шаг содержит:
   - действие,
   - **проверяемый критерий готовности** (exit criterion), а не просто глагол.

## Формат шага плана
```
❌ Плохо:  "Запустить тесты"
✅ Хорошо: "Запустить `npm test`; готово, когда exit code = 0 и нет fail."
```

## Правила
- НЕ начинать писать код до того, как пользователь утвердил план.
- Каждый шаг — атомарный и проверяемый.
- В конце плана указать Definition of Done (сборка + тесты зелёные + diff просмотрен).

## Финальный вывод
Показать пользователю: список шагов с критериями готовности + вопрос «Утверждаем план?». Стоять до ответа.
