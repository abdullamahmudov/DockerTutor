# План: голосовой ввод в Cline (Variant 1)

## Цель

Добавить кнопку микрофона рядом с кнопкой `PlusIcon` («Add Files & Images») в чат-инпуте расширения Cline и распознавать речь через **Web Speech API** прямо в webview. Результат диктовки подставляется в текстовое поле ввода сообщения.

### Целевые метрики
- Пользователь нажимает кнопку микрофона → говорит → текст появляется в поле ввода.
- Повторное нажатие останавливает запись и фиксирует транскрипт.
- При отсутствии поддержки API или отказе от доступа к микрофону — кнопка скрывается / показывается понятная ошибка, без падения UI.

### Критерии приёмки (Definition of Done)
1. Кнопка микрофона отображается в строке управления чатом рядом с «Add Files & Images» и визуально соответствует соседним кнопкам (размер, отступы, hover-состояние).
2. Нажатие кнопки запрашивает доступ к микрофону; при разрешении начинается запись, иконка меняет состояние на «запись».
3. Распознанный текст вставляется в поле ввода сообщения по позиции курсора (или дописывается в конец), без потери уже набранного текста.
4. Повторное нажатие останавливает запись; итоговый транскрипт фиксируется в поле.
5. В средах без поддержки Web Speech API кнопка не отображается, ошибок в консоли нет.
6. При отказе от доступа к микрофону показывается понятное сообщение пользователю (по паттерну существующих ошибок компонента).
7. Существующие unit-тесты webview-ui проходят без регрессий; добавлены тесты на новый хук распознавания речи.

### Вне рамок (Out of Scope)
- Распознавание на стороне extension host через локальный Whisper/WASM — отдельная, более тяжёлая задача.
- Голосовые команды управления интерфейсом (не только диктовка текста).
- Мультиязычное переключение языка распознавания в рантайме (используется язык локали VS Code).
- Сохранение аудиофайлов и постобработка транскрипта (ИИ-очистка, пунктуация) — базовая пунктуация предоставляется самим API.

## Контекст (что уже известно из кода)

Файл: `apps/vscode/webview-ui/src/components/chat/ChatTextArea.tsx` (~59 КБ).

- **Точка вставки** — строки ~1643–1662: блок `<Tooltip>` с кнопкой «Add Files & Images» (`PlusIcon`, стр. 1658), внутри `ButtonGroup`.
- **Паттерн кнопки**: `Tooltip` → `TooltipContent` (текст) → `TooltipTrigger` → `VSCodeButton appearance="icon"` + `aria-label` + `data-testid` + `onClick` → `ButtonContainer` → иконка из `lucide-react`.
- **Стили** (`styled-components`, стр. 125–141): `ButtonGroup` (flex, gap 4px), `ButtonContainer` (flex, gap 3px). Новая кнопка встраивается по тому же паттерну — дополнительных стилей не требуется.
- **Импорты уже на месте**: `VSCodeButton`, `Tooltip/TooltipContent/TooltipTrigger`, иконки из `lucide-react`. Нужно добавить только `MicIcon` (и опционально `Square`).

### Зависимости и предположения
- React + TypeScript, styled-components — текущий стек webview-ui Cline.
- Web Speech API (`SpeechRecognition`) доступен в движке Chromium, используемом VS Code; на Windows/macOS работает из коробки при разрешении ОС.
- Локаль пользователя доступна через существующие механизмы расширения (для настройки `lang` распознавателя).

## Шаги реализации

### Шаг 1 — UI: кнопка микрофона
**Цель:** визуально неотличимая от соседей кнопка, которая запускает/останавливает запись.

- Импортировать `MicIcon` из `lucide-react`.
- Вставить новый блок `<Tooltip>…<VSCodeButton>` сразу после кнопки «Add Files & Images» (после стр. 1662), до `<ServersToggleModal />`.
- Свойства: `aria-label="Voice Input"`, `data-testid="voice-button"`, тот же `className` и структура, что у соседних кнопок.
- Визуальное состояние записи: при `isListening === true` — сменить иконку на «стоп» (или добавить пульсирующую подсветку), обновить текст тултипа («Stop recording»).

### Шаг 2 — Хук распознавания речи
**Цель:** изолированная, переиспользуемая логика Web Speech API.

Новый файл: `apps/vscode/webview-ui/src/hooks/useSpeechRecognition.ts`.

- Обёртка над `window.SpeechRecognition || window.webkitSpeechRecognition` (с проверкой поддержки).
- Настройки распознавателя: `continuous = true`, `interimResults = true`, язык — из локали VS Code.
- События:
  - `onresult` → накапливать final-фрагменты, отдавать interim-текст для live-превью;
  - `onend` / `onerror` → сбросить состояние записи, передать ошибку наружу.
- Публичный API хука: `{ isSupported, isListening, start(), stop(), transcript }`.

### Шаг 3 — Встраивание в ChatTextArea
**Цель:** связать кнопку с полем ввода без нарушения существующего поведения.

- Вызвать `useSpeechRecognition` внутри компонента.
- При старте записи: запомнить текущее значение поля и позицию курсора (чтобы транскрипт вставлялся корректно).
- По остановке: дописать/вставить финальный транскрипт через существующий `setInputValue`.
- Обработка ошибок по уже имеющемуся паттерну компонента (`showDimensionErrorMessage`): сообщение об отказе от микрофона / отсутствии поддержки.

### Шаг 4 — Права и ограничения среды
**Цель:** корректное поведение в webview VS Code (Electron).

- Webview использует движок Chromium: `getUserMedia`/Speech Recognition обычно доступны, но требуется разрешение ОС на доступ к микрофону для процесса VS Code.
- Safari/iOS поддерживают только `webkitSpeechRecognition`; на Linux без соответствующего движка API может отсутствовать → кнопка скрывается gracefully (по `isSupported`).

### Шаг 5 — Тестирование
**Цель:** убедиться, что фича работает и ничего не сломано.

1. Dev-build расширения (`npm run watch` / F5 в VS Code).
2. Проверить сценарии: старт записи → диктовка → остановка → текст в поле; повторный старт; ошибка «нет микрофона»; среда без поддержки API (кнопка скрыта); тултип и aria-атрибуты.
3. Прогнать существующие unit-тесты webview-ui, затронувшие `ChatTextArea`.

### Шаг 6 — Документация и релиз
**Цель:** пользователь и команда знают о новой возможности.

- Обновить README / changelog расширения: описание кнопки микрофона, требования (разрешение микрофона в ОС), поддерживаемые платформы.
- При необходимости добавить строку в настройки/справку webview («Голосовой ввод»).

## Риски и альтернативы

| Риск | Митигация / альтернатива |
|---|---|
| Качество Web Speech API зависит от движка (на Windows/Chrome — хорошо) | Альтернатива: распознавание на стороне extension host через локальный Whisper (WASM) — надёжнее, но значительно больше работы. |
| Отказ ОС в доступе к микрофону | Понятное сообщение пользователю + скрытие кнопки при повторном отказе. |
| Разные браузерные движки (Safari vs Chromium) | Feature-detection через `isSupported`, graceful degradation. |

---

## Быстрая альтернатива без кода (для сравнения)

- **Windows: Win + H** — системная диктовка в любое выделенное поле, включая webview Cline. Работает из коробки, поддерживает русский.
- Сторонние инструменты с локальным Whisper (**Buzz**, **Wispr Flow**) — глобальная диктовка в активное поле с горячими клавишами и ИИ-очисткой текста.

Эти варианты дают голосовой ввод за минуты без изменения кода; Variant 1 нужен, если требуется именно нативная кнопка микрофона внутри чата Cline.
